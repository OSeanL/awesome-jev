## Sobre Jev impressionante

Awesome Jev é um catálogo independente, mantido pela comunidade de **530 projectos de código aberto** construído com [Jev](https://typesafe.ai/), Sistema de IA TipoSafe Um modelo para decisões digitadas dentro do software. Não é afiliado ou endossado pelo TypeSafe IA.

> **O que torna este catálogo útil?**
>
> Cada entrada identifica a decisão concreta que Jev toma e vincula às evidências públicas mais fortes disponíveis, para que você possa avaliar implementações reais, não apenas reivindicações de projetos.

## O que é Jev

Jev toma um **estado** mais um ou mais **perguntas** e retorna respostas estruturadas que o código pode usar diretamente. Não gera prosa.

Usá-lo para voltar
|---|---|---|
□ [«Escolha `](https://docs.typesafe.ai/primitives/choice) □ Selecione uma opção de um conjunto conhecido □ Opção selecionada, probabilidades, confiança
□ [«Score»](https://docs.typesafe.ai/primitives/score) □ Coloque alguma coisa em um rubric ordenado Pontuação, probabilidades de nível, confiança
□ [«Noul»](https://docs.typesafe.ai/primitives/noul) □ Estimar se uma declaração é verdadeira

Perguntas em uma solicitação compartilham o mesmo estado e são avaliadas de forma independente. As decisões complexas devem ser divididas em questões estreitas e compostas em código comum. A autorização, aritmética, limiares, efeitos colaterais e comportamento de retrocesso devem permanecer em código.

Novo em Jev? Comece com o oficial do TypeSafe [Introdução](https://docs.typesafe.ai/introduction), em seguida, continuar com [Primitivos](https://docs.typesafe.ai/primitives), [Confiança](https://docs.typesafe.ai/confidence), e [Padrões](https://docs.typesafe.ai/patterns).

## Por que esta lista existe

A maioria dos diretórios diz que um projeto usa o Jev. Esta lista também registra:

- Não. **O que Jev decide** — o julgamento exacto efectuado no âmbito do projecto.
- Não. **Anatomia da decisão** — state → question → respon → code action.
- Não. **Provas no local de chamada** — uma ligação à aplicação quando se é público.
- Não. **Estado da reprodução** — se existe ou não um livro de execução e se foi executado por um revisor independente.
- Não. **Procedência métrica** — oficial, autorreferida ou reproduzida de forma independente.
- Não. **Frescura** — a última data de revisão humana e o estado actual do projecto.
- Não. **Padrões reutilizáveis** — a arquitectura que transfere para outros produtos.

Otimizamos para inspecionabilidade e utilidade, não tamanho de lista ou estrelas GitHub.

## Como ler uma entrada

```text
Projeto — O que Jev decide.
Primitivo: Escolha · Padrão: Envio da ferramenta digitada
Evidência: Local de chamada verificado · Manutenção runbook · Metrics autor-reported
```

Os rótulos de verificação descrevem factos separados. Eles não são uma pontuação ou classificação.

Rótulo
|---|---|
□ **Fonte pública** □ O repositório é público e seu README descreve um fluxo de trabalho Jev concreto. □
□ **Local de chamada verificado** □ Um mantenedor localizou código público que chama Jev e consome sua resposta. □
□ **Apenas demonstração** □ Uma demonstração pública mostra o comportamento, mas nenhum site de chamadas foi encontrado. □
□ **README** □ O projeto upstream diz que usa o Jev; o site de chamada não foi verificado. □
□ **Runbook do mantenedor** □ O projeto upstream fornece instruções de configuração e execução. □
□ **Revisor reproduzido** □ Um revisor independente executou o fluxo de trabalho documentado e registrou a data. □
□ **métrica autorreferida** □ O número vem do autor do projeto e não foi reproduzido de forma independente. □
□ **Reproduzido por terceiros** □ Uma fonte pública separada repetiu a medição com um método documentado. □

## Critérios de inclusão

Um projeto listado deve:

1. Seja acessível ao público e citável.
2. Use explicitamente Jev, forneça um recurso oficial Jev, ou documento uma implementação independente Jev-style.
3. Tome uma decisão tipográfica concreta que pode ser descrita em uma frase.
4. Ligação com as provas mais fortes disponíveis.
5. Divulgue a relação do remetente com o projeto.

Um projeto faz **não** precisa de estrelas GitHub altas. O trabalho experimental e inicial é bem-vindo quando seu status e evidência são descritos com precisão.

Excluímos projetos genéricos de IA que se assemelham apenas a Jev, links lixões sem uma decisão concreta, fontes inacessíveis, documentação copiada e reivindicações de desempenho sem uma fonte rastreável.
